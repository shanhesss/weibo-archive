# 9. 语雀删除走 OpenAPI 直连，不走 MCP

- 日期：2026-08-30
- 状态：已接受（2026-08-30 经 /grill-with-docs 共识并实现，临时库 e2e 实测通过）

## 背景

归档删除（删语雀文档 + 微博重置为待归档）需要一个删远端文档的能力。
归档链路走无头 claude CLI + yuque MCP（ADR-0008），直觉上删除也应走同一条路，
但核查发现官方 `yuque-mcp`（19 个工具）只有 get/search/list/create/update 系列，
**没有任何删除工具**，且何时补上不受我们控制。

## 决策

- **删除 = 直连语雀 OpenAPI**（urllib，零新依赖）：`DELETE /api/v2/repos/:namespace/docs/:id`。
  库里只存文档 URL，故先从链接解析 `账号/知识库` 与文档 slug，再经文档列表接口
  按 slug 查数字 id（翻页上限 2000 篇，单库更大的知识库需换搜索接口），然后删除。
- **令牌复用**：运行时读取 `~/.claude/settings.json`（回退 `~/.claude.json` / 项目 `.mcp.json`）
  里已配置的 `YUQUE_PERSONAL_TOKEN`——与归档 MCP 用同一个，不新增配置项、不入代码、不入库。
- **404 视为成功**：文档或知识库已不存在（用户可能在语雀网页手动删过）时，删除目标已达成，
  照常清本地归档标记；其余失败保留原状态可重试。
- **归档与更新的路线不动**：仍走 MCP（ADR-0008）。MCP 提供建文档 + 挂目录 + AI 摘要一体，
  价值不在裸 API 可替代；删除只是一个裸 HTTP 动作，没必要为它起一个 claude 子进程。

## 后果

- 删除不消耗 claude 调用、不占 MCP 每日配额，秒级完成；代价是引入一条独立的语雀接入路径，
  语雀 API 变动要改两处认知（但删除接口语义稳定，风险低）。
- 令牌来源与归档绑定同一份配置：换了语雀账号要同时影响归档与删除，符合预期。
