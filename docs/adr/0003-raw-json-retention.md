# 3. 博文原始 JSON 落库留底（raw 留底）

- 日期：2026-08-19
- 状态：已接受

## 背景

一次全量爬取的代价很高：几万条博文要数小时，且顶着 432 反爬与账号风控风险。字段需求会随使用演化（发布工具、位置、话题等此刻都没进清洗字段，但 raw 里有）。

## 决策

posts 表除结构化清洗字段外，每条博文把 m 站接口返回的**原始 JSON** 整体存 `raw_json` 列。

## 备选方案

- **只存清洗字段**：省空间，但任何新字段需求都意味着带着风控风险重爬全量历史。

## 后果

- 库体积增大（粗估每条几 KB，几万条约几十~一二百 MB），磁盘可接受。
- 清洗逻辑出 bug 时可用 raw 重放修复，不必重爬。
- 将来若体积成为问题，可写脚本剥离最老博文的 raw，结构化字段保留。
