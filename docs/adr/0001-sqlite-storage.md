# 1. 用 SQLite 存储微博数据

- 日期：2026-08-19
- 状态：已接受

## 背景

本地工具需存储几千到几万条博文，前端查询页要按账号、关键词、日期区间筛选并分页。仓库现有工具（oms_devops_server.py）走纯标准库 + JSON 文件路线。

## 决策

用单文件 SQLite 存储，零外部依赖（Python 标准库 `sqlite3`），筛选/分页/索引全部交给 SQL。

## 备选方案

- **JSON 文件**（与 oms_devops_store.json 同款）：几千条里做筛选、分页、去重都要手写，查询页会痛。
- **MySQL**：团队熟悉（OMS 体系在用），但对本地自用工具偏重，引入连接配置依赖。

## 后果

- 后续若部署，SQLite 单文件可直接迁移；单进程写的并发限制对本工具不构成问题。
- 关键词筛选用 `LIKE '%kw%'`，如将来需要全文检索再引入 FTS5，不现在做。
