# 7. 博主主页链接 + 重拉全量 + 已删除标记

- 日期：2026-08-20
- 状态：已接受

## 背景

添加博主后需能拿到其主页链接（分享/定位）。更关键：拉取逻辑演进（表情/链接/长文修复）后，存量数据与新逻辑不一致；用户需要一种「重新全量拉取」手段，而不是手动删博主再重加。

## 决策

- **主页链接**：新增 `bloggers.homepage`，添加博主时写入 `https://weibo.com/u/{uid}`（由 uid 推导，无需用户额外提供）；博主行加「复制主页」小按钮。
- **重拉全量**：博主行新增「重拉全量」按钮 —— **不删除数据**，从头（page 1）全量重拉，逐条覆盖；全量拉到底后，把「本次未在微博上见到的博文」标记为【博主已删除】。中途暂停/出错时**不**做删除标记（避免翻页漂移误判），已拉部分保留、断点续爬。
- **断点机制**：统一复用 `next_page`，不与增量拉取区分 —— 重拉全量与首次全量同属 full 拉取，共用断点；增量拉取无断点、碰到已有即停。UI 已用状态（暂停→继续）区分，无需额外字段。
- **已删除标记**：新增 `posts.deleted`（0/1，默认 0）；任何一次拉取/更新见到该博文即置 0。**全量拉取的标记逻辑（修正后）**：用 `pull_seen` 表记录本次全量拉取中见到的所有博文 id（跨断点续爬持久保留，只在全新全量 page=1 时清空）——**拉取过程中不打任何标记**，只在**拉到底**时把 `id NOT IN pull_seen` 的博文一次性标记为已删除。这样既不会在拉取中途出现「先打标、翻到后又取消」的假象，也不会因断点续爬误判。**批量更新同样标记**：单条抓取失败且接口提示「该微博不存在/已删除」时置 1（实测返回 `ok:0,msg:"该微博不存在"`，不会误判为登录失效）；纯网络错误不误标。前端卡片显示【博主已删除】标签，筛选栏加「状态」筛选（全部/正常/已删除）。

## 后果

- 重拉全量不会清空数据，中断安全（断点续爬）；唯一副作用是微博已删博文会被标记而非清除。
- 标记逻辑只在 full 拉取**到底**时生效，增量/批量更新不会误标。
- 主页链接由 uid 推导，改名/自定义域名不影响。
