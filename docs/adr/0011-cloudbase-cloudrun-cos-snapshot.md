# 11. 迁移腾讯云托管（CloudRun）：COS 挂载盘快照式持久化、副本恒 1、去 nginx/systemd

- 日期：2026-09-26
- 状态：已接受（经 /grilling 共识；快照方案经一次性实测服务闸门验证）

## 背景

工具此前部署在腾讯轻量服务器（Ubuntu + systemd + nginx，见 `deploy/README.md`），
该服务器到期弃用。用户在多电脑上使用，需要一个 7×24 在线的公网部署；已开通
CloudBase 云托管个人版（19.9 元/月，含 4 万资源点，与个人其他服务同环境）。
云托管的关键约束打破了两条既有假设：

1. **无持久磁盘**：容器本地盘随实例回收消失，`weibo.db` 没地方放。
2. **个人版开不了 VPC → CFS 文件存储挂载不可用**（实测被平台拦截），SQLite 直挂
   共享盘的退路没了；对象存储挂载虽不要求 VPC，但不支持文件锁/随机写，
   SQLite 不能直接跑在上面。

另有约束：网关 60s 请求超时 / 20MB 请求体；空闲可缩 0（后台线程会死）；
挂载配置只在下次部署后生效；默认域名带浏览器提示页、仅测试用。

## 决策

### 快照式持久化（闸门实测 2026-09-26）

- 运行库放**容器本地盘**（`WEIBO_DB=/app/data/weibo.db`，真 SQLite 语义、WAL 随意用）。
- **写路径**：每 5 分钟（`SNAPSHOT_INTERVAL=300`，库无变更不上传）经 sqlite3
  `backup()` API 出一致性快照，`copyfile→.tmp→os.replace` 原子拷到对象存储挂载盘
  `/mnt/weibo/weibo.db`（`WEIBO_COS_DIR`）。收到 SIGTERM/SIGINT 时做最后一次快照再退出。
  管理员另有 `POST /api/admin/snapshot` 手动触发（升级前压丢失窗口）。
- **读路径**：实例启动时本地无库且挂载盘有快照 → 拉回本地再打开；恢复失败照常起
  （空库也要保证服务可用），快照文件本身因原子覆盖永不变脏。
- 实测数字：90MB 快照 2.9s、恢复 182ms、跨重部署 sha 一致 + integrity ok。
- **首次数据迁移 = 播种文件**：留档库（`weibo-server-final-20260926.db`）改名 `seed.db`
  上传到挂载目录；恢复时 `seed.db` 优先于快照且**一次性消费**（改名 `.used`）——
  不能直接覆盖快照位，否则空库实例的周期/SIGTERM 快照会在换血部署时把播种冲掉。
  快照位文件此后即**线上数据的最近备份**（控制台可随时下载）。

### 常驻与请求模型

- 副本 **min=max=1**：定时拉取/归档/快照全靠进程内后台线程，缩 0 即停摆；
  恒 1 同时天然杜绝双实例同写一份快照的竞态。0.25 核 0.5G 常驻约 14 元/月。
- 60s 网关超时不改架构：既有设计里 HTTP 请求只做入队/轮询，长任务本就在后台线程。
- 监听适配：`WEIBO_BIND=0.0.0.0` + 读平台注入的 `PORT`（不设 `WEIBO_BIND` 时行为
  与本地开发完全一致，仍绑 127.0.0.1）。

### 交付面

- 部署走 **CloudBase CLI 本地代码包**（`pack.sh` 产 `cloudbase-dist/`：
  3 个运行文件 + Dockerfile；云端构建，本机不装 Docker）。
- `weibo.db` 不进镜像、不进包；旧部署链（install.sh/nginx/systemd）从本分支删除，
  历史保留在 `main`。
- 域名（已定，2026-09-26）：个人版不升级（省 80 元/月），与同账号其他服务共用一个
  备案域名，按路径路由 `/weibo` → 本服务。应用做「前缀感知」：
  环境变量 `WEIBO_BASE_PATH` 一处开关（HTML 占位注入前端 `WB_BASE`、后端剥前缀、
  cookie Path 限定前缀），网关保留或剥除前缀均可工作；将来换独立子域名只需
  置空该变量重新部署，零代码改动。

## 备选方案

- **CFS 直挂跑库**：语义最正，个人版无 VPC，平台层不可行。
- **整个库定期下载-修改-上传**：并发写会互相覆盖；快照 + 单副本把窗口压到 ≤5 分钟。
- **换 Postgres/MySQL**：破「纯标准库零依赖」铁律（ADR-0001），改造量不成比例。
- **续轻量服务器 / Serverless 函数**：前者是正要弃用的方案；函数形态杀后台线程、
  60s 限制伤拉取，均否。
- **多副本 + 分布式锁**：为个位数用户引入锁服务，复杂度不值得；恒 1 副本够用。

## 后果

- **接受 ≤5 分钟的丢失窗口**：实例被强杀（非 SIGTERM 下线）时最多丢最近 5 分钟写入；
  重大批量操作后手动快照一次即可。
- 快照文件是全量库（~90MB）每次整拷，存储写入流量随库增长线性上升；量级下无感。
- 「库在挂载盘 = 备份」使应用内周期备份成为可推迟的增量项（用户已确认首版不做）。
- 部署文档、AGENTS/CONTEXT 的部署叙事整体从「Ubuntu+nginx」切到「云托管」；
  `deploy/cloudbase/README.md` 成为唯一现行手册。
- **分支即产品线（2026-09-26 用户拍板）**：本决策落在 `cloudbase-cloudrun` 分支，
  与 `main`（本地 exe / 云服务器形态）永久平行、互不合并；exe 打包与旧部署链文件
  在本分支删除，两线各自演进，接受一定代码重复。
