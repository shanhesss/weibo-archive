# 5. 查询页体验优化：卡片密度、图片缩略图、批量操作、长文全文

- 日期：2026-08-20
- 状态：已接受（2026-08-20 实证验证通过）

## 背景

首版布局上线后的反馈迭代：卡片太挤全带滚动条、图片显示为大图溢出被裁、灯箱鼠标切换无反馈、长文只能拿截断内容、缺少对筛选结果的批量处理、分页跳转失效。

## 决策

- **每页 6 张**：网格改为 3 列 × 2 行，卡片高度按视口剩余二等分（ADR-0004 的 3×3=9 作废）。
- **图片缩略化**：卡片使用微博 `bmiddle` 缩略档 URL（替代 `large` 原图），灯箱看大图仍用 `large`；同时修复 CSS 渲染 bug（grid 行高不定导致图片以自然大图尺寸溢出被裁）。
- **灯箱交互**：保留「点图=切下一张、点遮罩=关闭」，修复点击失效；图上加「点击切换 · ESC 关闭」提示，降低发现成本。
- **批量操作**：卡片勾选框 + 「全选本页」「全选当前筛选结果」；本页勾选翻页即清，全局模式跨页保留。批量操作只作用于勾选条目，跨博主筛选只动勾选、不碰其他博主。
  - **批量删除**：确认弹窗三个选项——删除 / 改为覆盖更新 / 取消。
  - **批量更新**：对选中博文整条重拉（正文含长文全文、互动计数、图片），新数据覆盖旧数据；未勾选不动。
- **长文全文**：最终方案走 `m.weibo.cn/statuses/show?id={mid}` —— 返回标准严格 JSON（`data` 即完整博文，含全文/计数/媒体）。此前 detail 页 `render_data` 是 JS 对象字面量（单引号键 + 值内撇号混用），`raw.replace("'", '"')` 一刀切会破坏 JSON 结构，导致部分长文补拉失败。已实证：批量更新把样例 `RefllFgve`（147 字截断→455 字）、`5331859881856522`（294→863 字）修复为完整正文。无有效登录态时该接口抛 ApiError，补拉依赖 cookie。
- **正文富文本**：`clean_text` 保留微博表情 `<img class="wemoji">`（face.t.sinajs.cn 无防盗链直连）与外部链接 `<a class="wlink" target="_blank">`（href 白名单 http/https）；前端 `richText()` 对普通文本转义、只放行这两类标签，防止注入。存量 428 条已迁移。
- **分页 bug**：重写为事件委托（`data-pg` 属性 + #filters 上的委托监听），杜绝内联绑定随 innerHTML 重建失效；同时请用户硬刷新排除缓存。
- **分页 bug**：现象为「有请求但页码、内容均不变」，判定为点击后请求未携带新页码；重写为事件委托绑定并本地复现验证。

## 后果

- 单页密度从 9 降至 6，浏览粒度更粗但单卡可读性显著提升。
- 批量更新是一次性全量抓取的替代路径，也承担长文修复的存量迁移职责。
