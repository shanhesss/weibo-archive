# 2. 走 m.weibo.cn 非官方接口 + 登录小号 cookie

- 日期：2026-08-19
- 状态：已接受

## 背景

需要拉取任意公开博主的全量历史博文（几千~几万条）。2026-08 调研（含实测）结论：

- **官方开放平台 API**：`statuses/user_timeline` 升级后读非授权用户**仅返回最新 5 条**，历史深度为零；个人开发者过审困难。
- **游客/免登录抓取**：2025 年后已被反爬升级封死 —— 裸请求与访客 cookie（Sina Visitor System）均遭 HTTP 432。
- **RSSHub 微博路由**：每次仅返回第一页（约 10 条），只能做增量订阅，做不了历史归档。

## 决策

采用 **m.weibo.cn `getIndex` 非官方接口**（containerid=230413+uid，page+count≤100 翻页）+ **登录小号的 SUB cookie**（浏览器登录后粘贴进工具，手动维护）。

- 单通道起步；PC 端 `weibo.com/ajax/statuses/mymblog` 作为**明确的**后备通道，仅在被持续封锁时再实现。
- cookie 失效（432）时前端红灯提示、人工重贴；不做验证码自动化。
- 速率对齐社区实践（dataabc/weibo-crawler）：页间随机间隔 6–10 秒。

## 后果

- 接口无稳定性承诺，字段变更/风控升级需跟进社区（weibo-crawler 为参考实现）。
- 小号有被风控/封禁的风险，由「只用无关紧要的小号」隔离，不用大号。
- cookie 数天~数周失效一次，重贴是常态操作，UI 必须把它做成一等公民。
