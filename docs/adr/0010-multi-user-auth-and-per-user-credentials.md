# 10. 多用户账号体系：邀请码注册、凭证按用户入库、语雀令牌来源改库

- 日期：2026-08-31
- 状态：已接受（2026-08-31 经 /grill-with-docs 共识，待实现）

## 背景

工具要部署到服务器，须防止部署地址泄漏或 API 暴露后被陌生人直接操作数据。
原设计是本地单用户：无任何鉴权、服务绑 127.0.0.1、小号 cookie 存全局 `kv` 键、
语雀令牌只从用户本机 claude 配置读取且明确「不入库」（ADR-0008、ADR-0009）。
多用户化同时改变了这三条。

## 决策

### 账号模型

- **邀请码注册**：单一全局码，管理员在后台查看/复制/重新生成；用户名唯一、
  3–16 位、不可修改；无邮箱。
- **内置 admin**：存量数据（博主/博文/全局 cookie/配置）首次启动自动迁移归 admin；
  初始密码由环境变量预设，未设则首次启动生成并打印到日志一次。
- **严格数据隔离**：内容（博主、博文）与凭证（小号 cookie、语雀令牌）全部按用户隔离，
  跨用户不可见，管理员也不看内容；管理后台只管账号：列表、禁用/启用、删除（连同数据、
  双重确认、含未注销用户）、重置密码（随机密码仅展示一次）、归档权限开关、邀请码管理。
- **注销**：用户自助，7 天反悔期——期间登录提示已注销并可「取消注销」完整恢复，
  到期自动清除数据并释放用户名（启动时 + 每日各检查一次）；管理员可提前清除。
  另有管理员「禁用」：无倒计时的强制停用，随时可启用。禁用/注销即时失效该用户全部会话。
- **归档权限开关**：语雀 AI 归档消耗服务器账号的 claude 与语雀 MCP 配额，
  普通用户默认关闭，管理员逐个放行；管理员默认开启。
- **隔离代价（已确认接受）**：每用户自备小号、自贴 cookie；同博主多人关注各拉各的；
  管理员不能代配置。

### 安全实现（延续纯标准库路线，零新依赖）

- 密码：PBKDF2-HMAC-SHA256 + 随机盐；登录失败 5 次锁 15 分钟。
- 会话：服务端会话存 SQLite，30 天滑动过期；cookie 置 HttpOnly + SameSite=Lax，
  HTTPS 后加 Secure。
- **凭证入库、不做加密**：Python 标准库无对称加密，而任何加密的主密钥仍存于同一台机器，
  防护上限不变；信任边界 = Linux 专用运行用户 + 数据目录权限（700/600）+
  界面与日志对 cookie/令牌全程打码（仅显示末 4 位）。
- **无本地豁免后门**：本机开发运行同样要登录。

### 语雀令牌来源变更（取代 ADR-0008/0009 的「读 claude 配置」）

- 令牌按用户存库；一切语雀操作（MCP 归档 + OpenAPI 删除）只认库中该用户的令牌，
  不再扫描 `~/.claude/settings.json` / `~/.claude.json` / `.mcp.json`。
- 迁移时执行一次既有 `load_yuque_token()` 扫描逻辑，把本机 claude 配置里的令牌
  自动导入 admin 名下，用户无需重贴。
- **归档调用带令牌 = 逐次 `--mcp-config`**：每次 spawn 无头 claude 时生成临时
  MCP 配置文件（注册 yuque-mcp、env 内放该用户令牌、权限 600、用后即删），
  不依赖也不污染服务器全局 claude 配置；服务器上无需注册任何全局 yuque MCP。
  实现时按 ADR-0008 惯例做 e2e 实测。

### 部署形态

- Linux 专用系统用户 + systemd；服务保持只监听回环（现 127.0.0.1:8766），
  nginx 反代 + 终结 TLS，域名与 HTTPS 同步上线；本地开发直接访问
  `http://localhost:8766`，不受影响。
- 服务器该用户下需具备：Node.js、claude CLI、claude 登录态。

## 备选方案

- **开放注册 / 注册审批**：开放会被发现地址的陌生人注册消耗配额；审批对个位数用户过重。
- **令牌存独立保密文件（0700/0600）**：防护等级与入库相同，多一套存取代码，无收益。
- **引入 `cryptography` 加密落库**：破零依赖先例；仅在「SQLite 备份需带离服务器」
  的场景才有实际意义，届时再议。
- **按用户注册 N 个 yuque MCP / 全局 env 注入**：前者管理失控；后者会被全局
  MCP 配置里写死的 env 覆盖，有隐性坑。
- **管理员可看内容 / 共享数据**：打破隔离且引入越权面，否决。

## 后果

- 数据库 schema 全面加用户归属（bloggers/posts/pull_seen/kv 拆分），难以回头；
  所有查询带 user_id 过滤，越权风险集中在迁移与过滤的完整性上，实现时需专项核对。
- 服务器上多了一份高价值凭证：claude 登录态，服务器被入侵 = Claude 账号暴露，无代码方案可解。
- 域名未上 HTTPS 前密码与会话明文传输，故要求 HTTPS 与服务同步上线。
- 被邀请用户须自备微博小号，否则只能浏览不能拉取。
- posts/bloggers 主键需并入用户维度（两人关注同博主各自独立存一份），库体积随用户数线性增长。
